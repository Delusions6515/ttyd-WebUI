# ttyd WebUI 使用指南

[English](usage.md) · [项目说明](../README.md)

用浏览器操作服务器上的终端，在手机上也能使用方向键、Tab、Ctrl 和 Alt。每个会话运行在 tmux 中：关掉网页不会结束任务，可以稍后重新连接。

> **先确认访问范围。** 本项目没有登录或用户权限管理。能访问页面的人可以使用服务账户的终端。不要直接暴露到公网；远程访问优先使用 SSH 隧道，或部署带认证的 HTTPS 访问网关。建议使用普通用户运行服务，不要使用 root。

## 1. 安装和启动

### 服务器需要什么

- Node.js 和 pnpm：安装依赖、构建页面和运行服务。
- [ttyd](https://github.com/tsl0922/ttyd) 和 [tmux](https://github.com/tmux/tmux)：提供终端连接和后台会话。
- POSIX shell，例如 Bash 或 sh；使用下面的下载命令还需要 Git。

这些程序需要安装在**运行服务的服务器上**，手机或其他客户端只需要浏览器。请按服务器的操作系统安装依赖，本项目不规定 Node.js 或 pnpm 版本。

先确认程序能找到：

```sh
node --version
pnpm --version
ttyd --version
tmux -V
```

### 下载并运行

当前应用代码在 `dev` 分支。以下命令从该分支下载：

```sh
git clone --branch dev https://github.com/Delusions6515/ttyd-WebUI.git
cd ttyd-WebUI
pnpm install --frozen-lockfile
cp .env.example .env
pnpm run build
pnpm start
```

在服务器本机的浏览器中打开 **http://127.0.0.1:3000**。服务在前台运行，请保持启动它的终端打开。按 `Ctrl+C` 可以停止服务；已有 tmux 任务仍会保留。

已经下载过项目时，直接进入项目目录操作即可，不需要再次 clone。修改 `.env` 后需要重新启动服务。

### 从另一台电脑访问：SSH 隧道

保留默认的本机监听地址，在客户端电脑运行：

```sh
ssh -N -L 3000:127.0.0.1:3000 user@server
```

把 `user@server` 换成服务器的 SSH 用户和地址，保持 SSH 连接打开，再在客户端浏览器访问 **http://127.0.0.1:3000**。如果客户端的 3000 端口已被占用，先关闭占用程序。

## 2. 创建和管理会话

1. 在手机上点左上角 **会话**；桌面端使用左侧会话列表。
2. 点 **New session**，选择服务器上可用的 Shell。
3. 名称可以留空，由程序自动分配；自定义名称只能使用英文字母、数字、下划线和连字符，例如 `work-shell`。
4. 点 **Create session**，连接完成后即可输入命令。

切换会话时，点击列表中的名称。桌面端可以折叠侧栏，给终端留出更多空间。

| 操作 | 会发生什么 |
|---|---|
| 关闭网页、刷新或暂时断网 | tmux 任务保留；连接恢复后可继续操作。断线期间输入的内容不会补发。 |
| **Stop** | 停止该会话的网页终端服务，保留 tmux 任务。 |
| **Resume** | 重新开放已停止会话的网页访问，连接到保留的任务。 |
| **Delete**，然后确认 | 结束该会话对应的 tmux 任务并移除记录。**不可撤销，任务中的程序也会被结束。** |
| 停止或重启整个 WebUI 服务 | 托管的 ttyd 进程停止，tmux 任务保留；服务重新启动后的会话列表为空。 |

**服务重启后，旧任务不会自动回到列表里。** 当前没有导入或恢复页面；同名新会话也不会接管旧任务，自动命名会跳过已占用名称。需要找回旧任务时，请看下方的“服务重启后会话不见了”。

## 3. 手机输入和快捷键

点击终端区域输入，或用顶部的 **显示键盘 / 隐藏键盘** 按钮请求打开、关闭软键盘。最终能否弹出键盘由手机浏览器和系统决定。

终端底部默认有两行快捷键：

```text
ESC   /   -   HOME   ↑   END   PGUP
TAB   CTRL   ALT    ←   ↓    →    PGDN
```

- **TAB**：发送 Tab，常用于 Shell 补全。
- **方向键、HOME、END**：编辑命令或操作终端程序。
- **ESC、PGUP、PGDN**：发送相应按键，具体效果由当前程序决定。
- **更多按键**：展开 F1–F12 和常用组合键。
- **CTRL / ALT**：点一下启用一次，再输入字符或点快捷键。一次发送后解除；再点一次可以取消。
- **长按 CTRL / ALT**：锁定该修饰键，适合连续输入组合键；点一下解除。

例如：点 **CTRL**，再输入 `c`，可以向终端发送 `Ctrl+C`；也可以在 **更多按键** 中直接点 **Ctrl+C**。它通常中断当前程序，而不是复制文本。复制请使用“工具”。

启用虚拟 CTRL/ALT 后，会出现 **组合输入** 框。在这里确认中文输入法候选后再发送；中文或多字符提交不会被强行改写成控制字符。粘贴和“输入长文本”保留原文，不应用虚拟修饰键。外接键盘的 Ctrl/Alt 组合键使用实际按下的修饰键，不消耗屏幕上的一次性修饰状态。

## 4. 复制、粘贴和查看历史

点击终端右上角 **工具**。

### 复制

- 先选中终端文本，再点 **复制所选文本**。
- 手机上不方便选择时，点 **打开复制视图**，在文本视图里选择并复制需要的内容。

复制视图展示打开时的终端缓冲区快照，不是持续更新的日志，也不包含已经从缓冲区中移除的历史。

### 粘贴和长文本

- 点 **粘贴**，尝试读取系统剪贴板。
- 如果浏览器拒绝剪贴板权限，按提示使用文本输入框手动粘贴。
- 点 **输入长文本**，编辑多行内容，然后选择 **发送文本** 或 **发送并回车**。

**发送文本**不会额外添加回车；**发送并回车**会在末尾加一个回车。多行内容本身可能包含换行，粘贴的命令也可能执行，请先检查内容。

剪贴板功能受权限和浏览器安全上下文限制。手机访问局域网 HTTP 地址时，自动复制或粘贴可能不可用；可以使用上述手动方式，或部署 HTTPS。

### 查看输出历史

在“工具”里点 **开始本地滚屏**，拖动终端查看历史，或用 **向上滚动 / 向下滚动**。点 **返回底部** 回到最新输出，再点 **结束本地滚屏** 恢复正常终端操作。

本地滚屏只移动浏览器里的终端视图，不向服务器程序发送方向键或滚轮输入。在编辑器等全屏程序里需要滚动内容时，应退出本地滚屏，再使用程序自己的按键。

## 5. 设置

顶部 **设置** 中可以：

- 调整终端字号（8–32 px）。
- 显示或隐藏快捷键栏。
- 编辑两行快捷键的名称和动作，包括终端按键、文字、Ctrl/Alt 修饰键及组合序列。
- 恢复默认配置。

编辑后点击 **保存**。这些偏好只保存在当前浏览器、当前站点中；换浏览器或清除站点数据后不会保留。终端输出和输入草稿不会存入浏览器本地存储。项目自带 Nerd Font，无需客户端另行安装字体。

## 6. 让手机在可信局域网中访问

仅在你信任该网络及所有访问者时使用此方式。它**不会增加登录保护**，普通 HTTP 也不加密流量。

假设服务器地址是 `192.168.1.10`，编辑项目根目录的 `.env`：

```dotenv
HOST=0.0.0.0
PORT=3000
TRUSTED_ORIGINS=http://192.168.1.10:3000
```

重启服务，按需将防火墙的 3000 端口限制为可信网段，然后在手机上打开 **http://192.168.1.10:3000**。不要做公网端口转发，也不要开放内部 ttyd 端口范围。

`TRUSTED_ORIGINS` 可以填写完整来源地址，或下文所示的左侧单级域名通配符。浏览器地址的协议和端口必须匹配，不带路径；多个地址用逗号分隔。它只是来源校验，不是用户身份验证。使用域名或 HTTPS 网关时，填写最终的浏览器访问地址，并确保代理支持 WebSocket、保留正确的 `Host` 和 `Origin`。页面不支持 iframe 嵌入。

## 7. Tailscale 访问

使用你自己的 tailnet DNS 后缀，可在 Tailscale 管理控制台的 DNS 页面查看。例如设备地址是 `server.tail1234.ts.net`，后缀就是 `tail1234.ts.net`。请换成实际后缀，并使用完整设备域名访问，不要只填写 MagicDNS 短名称。

### 通过 Tailscale Serve 使用 HTTPS

服务器和客户端都需要安装并连接 Tailscale。WebUI 保持仅监听本机，在 `.env` 中设置：

```dotenv
HOST=127.0.0.1
PORT=3000
TRUSTED_ORIGINS=https://*.tail1234.ts.net
```

重启 WebUI。要让 tailnet 内的设备通过 HTTPS 访问本机服务，在服务器上运行：

```sh
tailscale serve --bg http://127.0.0.1:3000
```

如果已经使用 Serve，请先检查现有配置，再修改代理路由。按提示启用 HTTPS，然后打开 Serve 显示的 HTTPS 地址，例如 `https://server.tail1234.ts.net`。通过 Tailscale 访问策略限制访问者；不要用 Funnel 将这个终端公开到互联网。

HTTPS 由前面的 Serve 提供，WebUI 自身仍以 HTTP 监听 `127.0.0.1:3000`。应用不会信任转发的主机或协议请求头。前提条件和管理方式见官方 [Tailscale Serve 文档](https://tailscale.com/docs/reference/tailscale-cli/serve)。

### 通过 Tailscale 网卡直接使用 HTTP

也可以绑定服务器实际的 Tailscale IP，例如：

```dotenv
HOST=100.64.0.10
PORT=3000
TRUSTED_ORIGINS=http://*.tail1234.ts.net:3000
```

替换 IP 和后缀，重启 WebUI，然后在已连接 Tailscale、启用 MagicDNS 的客户端访问 `http://server.tail1234.ts.net:3000`。域名通配符不会放行短主机名或 IP 地址；需要时请另外添加它们的完整来源地址。Tailscale 会加密网络传输，但浏览器仍将 HTTP 页面视为不满足剪贴板 HTTPS 条件的页面。

### 通配符会放行哪些地址

`https://*.tail1234.ts.net` 只允许后缀前有一个 DNS 标签：

| 浏览器来源地址 | 是否允许 |
|---|---|
| `https://server.tail1234.ts.net` | 允许 |
| `https://other-device.tail1234.ts.net:443` | 允许；443 是 HTTPS 默认端口 |
| `https://tail1234.ts.net` | 不允许 |
| `https://nested.server.tail1234.ts.net` | 不允许 |
| `https://server.another-tailnet.ts.net` | 不允许 |
| `http://server.tail1234.ts.net` | 不允许 |
| `https://server.tail1234.ts.net:8443` | 不允许；需要另外配置该端口 |

通配符必须位于域名最左侧。不支持裸 `*`、域名中间的通配符、端口通配符或 IP 地址通配符。**不要将整个 `*.ts.net` 加入信任列表。** 通配符信任所有匹配设备的来源地址，不只当前服务器；请仅配置设备和使用者均可信的后缀。Tailscale 访问策略和来源校验不会为应用增加用户权限管理或登录页面。

## 8. 常见问题

### 页面打不开

确认 `pnpm start` 仍在运行，并查看启动终端里的错误。默认地址只接受服务器本机访问；从其他设备访问请使用 SSH 隧道或上面的局域网配置。端口占用时，可修改 `.env` 的 `PORT`，并同步更新访问地址和相应的 `TRUSTED_ORIGINS`。

### 提示来源或主机不允许

检查地址栏中的协议、端口是否与 `TRUSTED_ORIGINS` 一致，主机名是否完整匹配，或符合你配置的单级域名通配符。更改 `.env` 后重启服务；不要用裸 `*`、整个 `*.ts.net` 或关闭校验来绕过错误。

### 创建会话失败

确认服务账户能执行 `ttyd`、`tmux` 和所选 Shell。自定义名称可能已被当前或保留的任务占用，换一个名称或留空。没有可用 ttyd 端口时，停止不需要的会话，或检查 `.env` 中的端口范围和实际占用情况。

### 服务重启后会话不见了

会话列表只保存在内存里，重启会清空列表，但旧 tmux 任务可能仍在运行。在服务器上，以运行 WebUI 的同一个账户查看：

```sh
tmux -L ttyd-webui list-sessions
tmux -L ttyd-webui attach-session -t '=work-shell'
```

将 `work-shell` 换成实际名称。如果改过 `TTYD_TMUX_SOCKET`，将 `ttyd-webui` 换成配置值。在 tmux 中按 `Ctrl+B`，松开后按 `D`，可以脱离而保留任务。不要用不带 `-L` 的命令管理这些会话，那会操作默认 tmux 服务。

### 断线后终端没有反应

先看顶部连接状态，再检查服务器和网络。网络等临时故障会尝试重连；明确停止的会话需要点 **Resume**，已删除的会话需要重新创建。断线期间输入不会自动重放，恢复连接后请自行确认命令是否执行。

### 手机键盘或中文输入行为不一致

浏览器不能保证控制系统键盘。可以重新点击终端或 **显示键盘**，长文本可改用“工具”里的文本框。Android Chrome 和 iOS Safari 的实体设备验证仍待完成；自动化浏览器测试不代表每台手机、输入法都已兼容。
